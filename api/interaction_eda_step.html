interaction_eda_step.fragments module#

The fragments of a structure for EDA.

By default each molecule of the configuration is a fragment. The molecules come from the bonds, and their charges from the atoms’ formal charges or, for known molecules (water, carbonates, Li⁺, BF₄⁻, PF₆⁻, monatomic ions), from seamm_mbe’s catalog, which also checks that every fragment has a sensible number of electrons. Alternatively an integer atom column (e.g. “fragment”) assigns the atoms to fragments, with charges summed from the formal charges.

interaction_eda_step.installer module#

Installer for the Interaction EDA plug-in.

The GPU4PySCF backend runs in its own conda environment, seamm-gpu4pyscf by default, which this installer creates and registers in gpu4pyscf.ini. The environment holds Python 3.12 from conda-forge and, from PyPI, GPU4PySCF with CuPy, cuTENSOR and the CUDA libraries for the machine’s NVIDIA driver, plus pyscf-dispersion for D3/D4. It needs Linux and an NVIDIA GPU with good double precision; on macOS nothing is installed.

interaction_eda_step.installer.BUILDS = {'cuda12x': ('gpu4pyscf-cuda12x>=1.9.1', 'cupy-cuda12x[ctk]', 'cutensor-cu12', 'pyscf-dispersion'), 'cuda13x': ('gpu4pyscf-cuda13x>=1.9.1', 'cupy-cuda13x[ctk]', 'cutensor-cu13', 'pyscf-dispersion')}#

The pip requirements for each CUDA build. cuda12x is the validated one (ARC, 2026-11-07: gpu4pyscf 1.9.1, cupy 14.2, cuTENSOR 2.8, CUDA 12.9).

class interaction_eda_step.installer.Installer(logger=<Logger interaction_eda_step.installer (WARNING)>)[source]#

Bases: InstallerBase

Handle the installation of GPU4PySCF for the Interaction EDA step.

  1. install creates the conda environment seamm-gpu4pyscf (Python 3.12) and installs GPU4PySCF in it for the machine’s NVIDIA driver, then checks that it imports and can use the GPU, and writes gpu4pyscf.ini. cuda-build in gpu4pyscf.ini (or --cuda-build) forces a build, e.g. on a cluster login node without a GPU.

  2. update upgrades GPU4PySCF and its CUDA libraries in that environment.

  3. check and show say what is installed and whether it works.

An environment named in gpu4pyscf.ini that SEAMM did not create, or an installation = local Python, is never changed.

interaction_eda_step.manybody module#

Many-body bookkeeping of EDA interaction energies, term by term.

Every EDA number is an interaction energy of a set of fragments, relative to the same fragments alone at the same geometry, so single fragments contribute nothing. For the fragments i, j, k, … of a cluster:

  • the 2-body part of a term is the sum over the pairs, E(ij);

  • ≥3-body (exact) = E(cluster) - Σ pairs E(ij). It needs the cluster and every pair, and it is exact;

  • the 3-body increment of a triple is, by inclusion–exclusion, ΔE(ijk) = E(ijk) - E(ij) - E(ik) - E(jk). Summed over the triples that were computed (e.g. those within a cutoff) it is the 3-body (triples, truncated) estimate. It is a truncated sum and must not be read as the ≥3-body total; with all triples, the difference between the two is the ≥4-body part.

Fragment sets are tuples of 0-based fragment indices in ascending order.

A base class for substeps in the Interaction EDA subflowchart.

The top-level InteractionEda step iterates over the substeps of its subflowchart and calls each substep’s run() method. Each substep is responsible for preparing its own input, invoking Interaction EDA, analyzing its output, and storing its results.

This base class provides:

  • options / global_options - delegated to the parent step so that command-line options reach substeps uniformly.

  • header - a printable header for this section of step.out.

interaction_eda_step.terms module#

The energy terms of each EDA scheme, and how they map onto common terms.

Each scheme keeps its own (“native”) terms, with the names the code uses. A few common terms let results from different schemes be put side by side, but only where the physics really is the same:

  • SAPT’s induction contains both polarization and charge transfer, so it maps to ALMO’s polarization plus charge transfer (“induction” here). Only schemes that split induction apart (ALMO-EDA) fill “polarization” and “charge transfer”; SAPT never does. Treating SAPT induction as polarization is the lumping that hides charge-transfer problems, e.g. for Li⁺.

  • “frozen” is ALMO’s frozen term (electrostatics + Pauli + dispersion). SAPT has no such term and leaves it empty.

  • SAPT’s electrostatics is the Coulomb interaction of the isolated monomers’ densities, which is ALMO’s classical electrostatic term (Q-Chem’s CLS ELEC). ALMO’s own “electrostatic” and “pauli” come from an orthogonal decomposition of the frozen wavefunction (Horn, Mao and Head-Gordon 2016; Q-Chem’s ELEC and PAULI) and are not comparable with SAPT: for PF6⁻–EC each differs from SAPT by 36 kJ/mol. So the common “electrostatics” is the classical term and the common “Pauli” is frozen − classical electrostatic − dispersion (Q-Chem’s MOD PAULI), within 2 kJ/mol of SAPT exchange. frozen = electrostatics + Pauli + dispersion holds in both sets, and the common ≥3-body electrostatics is exactly 0.

All energies are in kJ/mol.
